# Rider App API — App Integration Guide

Audience: mobile/app developer building the rider (delivery) app.
Base URLs, auth, envelopes and error shapes are the same for every
rider-app endpoint.

- **Base:** `/api/rider-app`
- **Auth:** `Authorization: Bearer <JWT>` — role `ROLE_RIDER`. There is **no**
  `/api/rider-app/auth` endpoint; riders log in through the shared auth API:
  - `POST /api/auth/login` — `{ "identifier": "<mobile>", "password": "...", "loginMethod": "PASSWORD" }`
  - OTP flow: `POST /api/auth/otp/request` — `{ "identifier": "<mobile>", "purpose": "LOGIN" }`
    → then `POST /api/auth/login` — `{ "identifier", "otp", "loginMethod": "OTP" }`
- **Headers:** `Content-Type: application/json`, `Accept: application/json`
- **Identity:** endpoints resolve the rider record from the token — no rider
  id is ever sent by the client. **The login mobile number must exactly equal
  `riders.phone`**, otherwise every call fails with
  `Rider not found for this user`.
- **Token lifetime:** 24 h. On 401, re-login.

### Login response (raw — not the standard envelope)

```json
{
  "token": "eyJhbGciOi...",
  "username": "9812345678",
  "name": "Suresh Yadav",
  "role": "ROLE_RIDER",
  "personId": 88,
  "tenantId": 3,
  "tenantType": "WAREHOUSE",
  "permissions": { }
}
```

Verify `role === "ROLE_RIDER"` and store `token`.

## Delivery lifecycle

```
ASSIGNED --picked--> PICKED --out-for-delivery--> OUT_FOR_DELIVERY --delivered--> DELIVERED (terminal)
   |                    |                            |
   +------failed--------+------------failed----------+-----> FAILED (terminal)
```

Allowed transitions (anything else → 400 `Invalid status transition from X to Y`):

| From | Allowed next |
|---|---|
| `ASSIGNED` | `PICKED`, `FAILED` |
| `PICKED` | `OUT_FOR_DELIVERY`, `FAILED` |
| `OUT_FOR_DELIVERY` | `DELIVERED`, `FAILED` |
| `DELIVERED` / `FAILED` | — (terminal) |

Each transition also mirrors the sales-order status:
`RIDER_ASSIGNED → SHIPPED → DELIVERED`, and **`FAILED` reverts the order to
`PACKED`** (it goes back into the pack queue for re-assignment).

## Envelopes

Success (all endpoints):

```json
{ "success": true, "message": "Orders fetched successfully", "data": [ ... ] }
```

Error:

```json
{
  "traceId": "ab12cd34",
  "error": "BUSINESS_ERROR",
  "message": "Assignment not found",
  "status": 400,
  "fieldErrors": null,
  "timestamp": "2026-10-13T12:00:00"
}
```

Validation errors use `"error": "VALIDATION_ERROR"` with
`fieldErrors: [{ "field": "newPassword", "message": "Password must be between 6 and 100 characters" }]`.

> **Exception — maps:** `GET /maps/route` always returns HTTP 200 with
> `message: null`; failures come back inside `data` as `{ "error": "..." }`.
> See §1.4 / §2.12.

## 1. Objects

### 1.1 Assignment (`RiderAssignmentDto`)

Returned by the orders and status endpoints. This is the rider's unit of
work — one row per order ↔ rider pairing.

```json
{
  "id": 701,
  "orderId": 501,
  "orderNumber": "SO-2026-00412",
  "riderId": 31,
  "riderName": "Suresh Yadav",
  "riderPhone": "9812345678",
  "status": "ASSIGNED",
  "assignedAt": "2026-10-13T11:30:00",
  "pickedAt": null,
  "outForDeliveryAt": null,
  "deliveredAt": null,
  "failedAt": null,
  "failureReason": null,
  "deliveredProof": null,
  "deliveryNotes": null,
  "crtDt": "2026-10-13T11:30:00",
  "crtBy": 1,
  "lstUpdtBy": null,
  "lstUpdtDt": null,
  "warehouseName": "YBM Main Warehouse",
  "warehouseAddress": "Plot 4, MIDC, Pune, Maharashtra - 411019",
  "warehouseLatitude": 18.5204,
  "warehouseLongitude": 73.8567,
  "customerName": "Priya Sharma",
  "customerPhone": "9898989898",
  "deliveryAddress": "Flat 3B, Lotus Residency, Baner, Pune - 411045",
  "customerLatitude": 18.5590,
  "customerLongitude": 73.7868,
  "grandTotal": 2499.00,
  "unloadingCharge": 0.00,
  "paymentMethod": "COD",
  "orderItems": [
    { "productName": "Classic Cotton T-Shirt", "variantLabel": "Size: M, Color: Navy", "sku": "TSH-M-NVY", "orderedQty": 2, "lineTotal": 958.00 }
  ]
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | number | **Assignment id** — the `{assignmentId}` path param |
| `orderId` / `orderNumber` | number / string | Underlying sales order |
| `riderId` / `riderName` / `riderPhone` | — | Me |
| `status` | string | `ASSIGNED` \| `PICKED` \| `OUT_FOR_DELIVERY` \| `DELIVERED` \| `FAILED` |
| `assignedAt`, `pickedAt`, `outForDeliveryAt`, `deliveredAt`, `failedAt` | string \| null | ISO-8601; null until that transition happens |
| `failureReason` | string \| null | Set on `FAILED` (max 500 chars — see §3) |
| `deliveredProof` | string \| null | Free-form proof (e.g. photo URL/reference) set on `DELIVERED` |
| `deliveryNotes` | string \| null | Free-form notes set on `DELIVERED` |
| `warehouseName` / `warehouseAddress` | string | Pickup point; address formatted `"line1, city, state - pin"` |
| `warehouseLatitude` / `warehouseLongitude` | number \| null | Pickup GPS — feed to maps |
| `customerName` / `customerPhone` | string | From the shipping address snapshot (fallback: customer profile) |
| `deliveryAddress` | string | Drop address snapshot |
| `customerLatitude` / `customerLongitude` | number \| null | Drop GPS — feed to maps; `null` if not captured |
| `grandTotal` | number | Order total (COD collection reference) |
| `unloadingCharge` | number \| null | Add-on charge on the order |
| `paymentMethod` | string | `COD` → collect cash; otherwise prepaid |
| `orderItems` | `OrderItemInfo[]` | Manifest — see below |
| `crtDt`, `crtBy`, `lstUpdtBy`, `lstUpdtDt` | — | Audit; safe to ignore |

**`OrderItemInfo`:** `{ productName, variantLabel, sku, orderedQty, lineTotal }`
(strings + number). Show as the package manifest / delivery checklist.

### 1.2 Lists: active vs history

| Endpoint | Contains | Order |
|---|---|---|
| `GET /orders` | Assignments with status ≠ `DELIVERED`/`FAILED`, on orders not `CANCELLED` | newest `assignedAt` first |
| `GET /orders/history` | **All** assignments (any status, incl. failed/cancelled-order rows) | newest `assignedAt` first |

No pagination — the full lists are returned. Poll `/orders` (the web UI
polls every 30 s) or refresh on app resume.

### 1.3 Profile (`RiderProfileDto`)

```json
{
  "riderId": 31,
  "name": "Suresh Yadav",
  "phone": "9812345678",
  "email": "suresh@example.com",
  "vehicleType": "BIKE",
  "status": "active",
  "licenseNumber": "MH12-2020-0012345",
  "idCardType": "AADHAR",
  "idCardNumber": "XXXX-9012",
  "address": "Pune, MH",
  "rating": 4.6
}
```

`status` is a free string — in practice `"active"` or `"inactive"` (not
ONLINE/OFFLINE). Profile fields are **read-only** in the rider app; edits
(name, phone, vehicle, documents, …) are admin-only.

### 1.4 Route (`data` of `GET /maps/route`)

On success `data` is the **raw Google Routes API v2 response** (field-masked):

```json
{
  "routes": [
    {
      "distanceMeters": 8400,
      "duration": "1260s",
      "polyline": { "encodedPolyline": "wouL_IqvmM..." },
      "legs": [
        {
          "duration": "1260s",
          "distanceMeters": 8400,
          "startLocation": { "latLng": { "latitude": 18.5204, "longitude": 73.8567 } },
          "endLocation": { "latLng": { "latitude": 18.5590, "longitude": 73.7868 } }
        }
      ]
    }
  ]
}
```

Read `data.routes[0].distanceMeters`, `.duration` (seconds string, e.g.
`"1260s"`), and decode `.polyline.encodedPolyline` for the map path.

On failure `data` is an error object — still HTTP 200, `success: true`:

| `data.error` | Meaning |
|---|---|
| `Google Maps API key not configured` | Server has no maps key |
| `No routes found` | Google returned no route |
| `Failed to fetch route: {msg}` | Upstream error |

Always check `data.routes` before using it.

## 2. Endpoints

| # | Method | Path | Payload | Response `data` |
|---|---|---|---|---|
| 2.1 | GET | `/api/rider-app/orders` | — | `Assignment[]` (active) |
| 2.2 | GET | `/api/rider-app/orders/history` | — | `Assignment[]` (all) |
| 2.3 | GET | `/api/rider-app/orders/{assignmentId}` | — | `Assignment` |
| 2.4 | PUT | `/api/rider-app/orders/{assignmentId}/picked` | — | `Assignment` |
| 2.5 | PUT | `/api/rider-app/orders/{assignmentId}/out-for-delivery` | — | `Assignment` |
| 2.6 | PUT | `/api/rider-app/orders/{assignmentId}/delivered` | `{ failureReason?, deliveredProof?, deliveryNotes? }` (optional) | `Assignment` |
| 2.7 | PUT | `/api/rider-app/orders/{assignmentId}/failed` | same optional body | `Assignment` |
| 2.8 | PUT | `/api/rider-app/location` | `{ "latitude", "longitude" }` | `"Location updated"` |
| 2.9 | GET | `/api/rider-app/profile` | — | `Profile` |
| 2.10 | PUT | `/api/rider-app/profile/password` | `{ currentPassword, newPassword }` | `"Password updated"` |
| 2.11 | PUT | `/api/rider-app/profile/status` | **none** (toggles) | `Profile` |
| 2.12 | GET | `/api/rider-app/maps/route` | query: `originLat`, `originLng`, `destLat`, `destLng` | Google Routes body |

### 2.1 Get active orders

```
GET /api/rider-app/orders
```

No payload. My assignments that are still in progress (§1.2), message
`Orders fetched successfully`.

### 2.2 Get order history

```
GET /api/rider-app/orders/history
```

All my assignments, any status, message `Order history fetched successfully`.

### 2.3 Get order details

```
GET /api/rider-app/orders/{assignmentId}
```

Single `Assignment` (§1.1), message `Order details fetched successfully`.
**Ownership-checked** — an id not belonging to you → 400 `BUSINESS_ERROR`
`Assignment not found`.

### 2.4 Mark picked up (`ASSIGNED` → `PICKED`)

```
PUT /api/rider-app/orders/{assignmentId}/picked
```

No body. Sets `pickedAt`, moves the order to `SHIPPED`. Response is the
updated `Assignment`, message `Order marked as picked up`.

### 2.5 Mark out for delivery (`PICKED` → `OUT_FOR_DELIVERY`)

```
PUT /api/rider-app/orders/{assignmentId}/out-for-delivery
```

No body. Sets `outForDeliveryAt`. Response is the updated `Assignment`,
message `Order marked as out for delivery`.

### 2.6 Mark delivered (`OUT_FOR_DELIVERY` → `DELIVERED`)

```
PUT /api/rider-app/orders/{assignmentId}/delivered
```

Request body — **all fields optional** (send `{}` or omit the body entirely):

```json
{
  "failureReason": null,
  "deliveredProof": "https://.../pod-photo.jpg",
  "deliveryNotes": "Left with the gate guard"
}
```

| Field | Notes |
|---|---|
| `deliveredProof` | Free-form proof reference (e.g. uploaded photo URL, OTP, signature note) |
| `deliveryNotes` | Free-form notes |
| `failureReason` | Ignored on this endpoint (used by `/failed`) |

Non-null values are written to the assignment; `null`/absent fields are left
unchanged. Terminal state — sets `deliveredAt`, order → `DELIVERED`.
Response is the updated `Assignment`, message `Order marked as delivered`.

### 2.7 Mark failed (→ `FAILED`)

```
PUT /api/rider-app/orders/{assignmentId}/failed
```

Request body — **all fields optional**:

```json
{ "failureReason": "Customer not reachable", "deliveryNotes": "Tried calling twice" }
```

| Field | Notes |
|---|---|
| `failureReason` | **Send this** — shown in history/admin. Column is `varchar(500)`: longer text fails at the DB (HTTP 500), so cap at 500 chars client-side. |
| `deliveryNotes` | Free-form notes |
| `deliveredProof` | Ignored on this endpoint |

Terminal state — sets `failedAt`; the **order reverts to `PACKED`** for
re-assignment. Response is the updated `Assignment`, message
`Order marked as delivery failed`.

### 2.8 Update GPS location

```
PUT /api/rider-app/location
```

Request:

```json
{ "latitude": 18.5308, "longitude": 73.8478 }
```

Raw JSON object with keys `latitude` / `longitude` (numbers). No validation —
send both; the last write wins (stored on the rider record, not a history
table). Response `data`: `"Location updated"` (message
`Location updated successfully`). Errors: `Rider not found` (400).
Call periodically (e.g. every 30–60 s) while on an active delivery.

### 2.9 Get profile

```
GET /api/rider-app/profile
```

Returns `Profile` (§1.3), message `Profile fetched successfully`.
400 `BUSINESS_ERROR` `Rider not found` if no rider record matches the
login mobile.

### 2.10 Change password

```
PUT /api/rider-app/profile/password
```

Request:

```json
{ "currentPassword": "old-pass-1", "newPassword": "new-pass-1" }
```

| Field | Rules |
|---|---|
| `currentPassword` | `@NotBlank` → 400 `VALIDATION_ERROR` `Current password is required`. Must match stored password (`Current password is incorrect` otherwise). Skipped only when the account is OTP-only. |
| `newPassword` | `@NotBlank` (`New password is required`) + 6–100 chars (`Password must be between 6 and 100 characters`). |

Response `data`: `"Password updated"` (message
`Password updated successfully`).

### 2.11 Toggle availability

```
PUT /api/rider-app/profile/status
```

**No body** — pure toggle of `riders.status` between `active` and
`inactive` (any JSON body you send is ignored). Response is the updated
`Profile` (§1.3); message is `Status updated to active` or
`Status updated to inactive` — key off `data.status`, or parse the message.

> Note: the rider's own toggle changes availability only; it does **not**
> disable login. (The admin-side toggle does both.)

### 2.12 Get route (navigation)

```
GET /api/rider-app/maps/route?originLat={n}&originLng={n}&destLat={n}&destLng={n}
```

| Query param | Type | Required |
|---|---|---|
| `originLat` / `originLng` | number | yes — e.g. `warehouseLatitude`/`warehouseLongitude` |
| `destLat` / `destLng` | number | yes — e.g. `customerLatitude`/`customerLongitude` |

Missing param → 400 `VALIDATION_ERROR` `Required parameter 'x' is missing`.

Response: HTTP 200 with `message: null`; `data` = Google Routes body or an
error object — see §1.4. Drive mode: TRAFFIC_AWARE, DRIVE, metric,
`languageCode en-IN`.

## 3. Errors to handle

| Status | `error` | `message` |
|---|---|---|
| 400 | `BUSINESS_ERROR` | `Assignment not found` (ownership check on GET detail) |
| 400 | `BUSINESS_ERROR` | `Rider assignment not found with id: {id}` (status PUTs, unknown id) |
| 400 | `BUSINESS_ERROR` | `Invalid status transition from {CURRENT} to {NEXT}` (wrong order, or repeat call) |
| 400 | `BUSINESS_ERROR` | `Rider not found` (profile/location when rider record missing) |
| 400 | `BUSINESS_ERROR` | `Rider not found for this user` (login mobile ≠ `riders.phone`) |
| 400 | `BUSINESS_ERROR` | `Login record not found` / `Current password is required` / `Current password is incorrect` |
| 400 | `VALIDATION_ERROR` | password rules (§2.10); missing maps query param |
| 401 | `UNAUTHORIZED` | `Session expired. Please login again.` / `Account has been disabled` / `Invalid credentials` |
| 403 | `FORBIDDEN` | `You do not have permission` (token role ≠ RIDER) |
| 500 | `DATABASE_ERROR` / `INTERNAL_SERVER_ERROR` | `failureReason` > 500 chars hits the DB limit; otherwise generic |

**Gotchas**

- Status PUTs are **not** ownership-scoped server-side — only send your own
  assignment ids (from `GET /orders`).
- `GET /orders/history` includes failed and cancelled-order rows; filter by
  `status` for a "completed" tab.
- There is **no stats/summary endpoint** and **no profile-edit endpoint** —
  compute counters client-side; profile changes go through admin.
- Maps failures are HTTP 200 with `data.error` — never treat 200 as "route ok".

## 4. Recommended app flow

1. **Login** → `POST /api/auth/login`, store `token`; verify
   `role === "ROLE_RIDER"`.
2. **Work list** → `GET /orders`; render per assignment: order number,
   `status`, COD amount (`paymentMethod === "COD"` → show `grandTotal`),
   customer name/phone, `deliveryAddress`, and the `orderItems` manifest.
3. **Navigate** → `GET /maps/route` with warehouse coords (pickup) or
   customer coords (drop); decode `routes[0].polyline.encodedPolyline`;
   handle `data.error` by falling back to the platform map app.
4. **Status buttons**, in lifecycle order (disable out-of-order actions
   client-side using the transition table):
   - Picked up → `PUT .../picked`
   - Out for delivery → `PUT .../out-for-delivery`
   - Delivered → upload proof → `PUT .../delivered` with
     `{ "deliveredProof": "<url>", "deliveryNotes": "..." }`
   - Could not deliver → reason picker → `PUT .../failed` with
     `{ "failureReason": "<≤500 chars>" }`
   Each returns the updated assignment — re-render from it.
5. **Location sharing** → `PUT /location` every 30–60 s while an assignment
   is active (and on significant movement).
6. **Availability** → `PUT /profile/status` toggle when going on/off shift;
   show `data.status`.
7. **Polling** → re-fetch `/orders` every ~30 s or on app resume; on 401,
   re-login.
